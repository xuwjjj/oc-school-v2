# خطة التطوير المقترحة — منظومة إدارة المدارس

هذه خطة عملية مقسّمة على مراحل، مرتّبة حسب الأثر مقابل الجهد.

---

## الوضع الحالي (ما يشتغل اليوم)

- تسجيل طالب كامل (بيانات شخصية + بطاقة وطنية + معلومات دراسية + صورة).
- شاشة دخول بثلاثة تبويبات (مشرف/طالب/إنشاء حساب).
- لوحة قيادة، سجل طلبة، حضور وغياب، درجات، امتحانات، كادر، منشورات، تقارير.
- قاعدة بيانات SQLite محلية + API محمي بالأدوار.

---

## المرحلة 1 — إكمال دورة الطلب (أعلى أولوية، 1–2 أسبوع)

| الميزة | الفائدة |
|---|---|
| **مراجعة الطلبات**: شاشة للمشرف يعرض الطلبات `pending` مع زر قبول/رفض وسبب الرفض | الطلب يصير دورة كاملة بدل تسجيل مباشر |
| **صفحة ملف الطالب**: كل البيانات + الصورة + الحضور + الدرجات في مكان واحد | بديل عملي عن الجداول الطويلة |
| **تصدير الطلب PDF/طباعة** بنفس ترتيب الأقسام الثلاثة | يستخدم في المدرسة والأرشيف الورقي |
| **إشعار تيليجرام** عند تسجيل طالب جديد أو قبول طلبه | المشرف يعرف فوراً |
| **سجل تدقيق** (من فعل ماذا ومتى) | مساءلة وأمان |

**تقنياً:** جداول `registration_requests` و`audit_log`، endpoints `/api/requests`، صفحة React جديدة.

---

## المرحلة 2 — تجربة استخدام أفضل (2–4 أسابيع)

- **بحث وترقيم صفحات** في سجل الطلبة (اليوم الجدول يعرض الكل).
- **فلترة** حسب الصف/الشعبة/الحالة/الجنس.
- **استيراد أذكى**: معاينة قبل الحفظ + كشف الأعمدة تلقائياً + تقرير أخطاء.
- **رفع الصور إلى مجلد/تخزين خارجي** بدل base64 داخل قاعدة البيانات (يقلّل حجم القاعدة كثيراً).
- **PWA**: تثبيت التطبيق على الجوال وعمل جزئي بدون إنترنت.
- **وضع فاتح/داكن** + تحسين الخط العربي (Cairo/Tajawal).
- **تحقق من صحة المدخلات**: الهاتف العراقي، تاريخ التولد، الرقم الوطني (تنسيق).

---

## المرحلة 3 — قدرات مدرسية أعمق (1–2 شهر)

- **الدرجات بأوزان**: امتحان شهري/نهائي بنسب، ومعدل تلقائي.
- **جدول الدروس الأسبوعي** + تعارضات القاعات.
- **QR للحضور**: الطالب يمسح رمزاً في الصف.
- **الرسوم والأقساط**: تسجيل دفع، متأخرات، إيصالات.
- **بوابة ولي الأمر**: يرى حضور ابنه ودرجاته وإشعاراته.
- **تقارير متقدمة**: تصدير Excel/PDF، مقارنة صفوف، مؤشرات أداء.
- **دعم عدة مدارس (Multi-tenant)** إذا كان النظام سيُستخدم في أكثر من مدرسة.

---

## تحسينات تقنية (تسير بالتوازي)

1. **اختبارات آلية**: Vitest للواجهة + Supertest للـ API (ابدأ بمسارات المصادقة).
2. **CI على GitHub Actions**: تثبيت + بناء + اختبار عند كل دفعة.
3. **متغيرات بيئة منفصلة** (تطوير/إنتاج) وعدم تشغيل الإنتاج بكلمة مرور افتراضية.
4. **نسخ احتياطي تلقائي** لـ `school.db` كل يوم + استعادة مجرّبة.
5. **مراقبة الأخطاء** (Sentry أو بديل) وسجلات منظمة.
6. **ترحيل قاعدة البيانات** من SQLite إلى PostgreSQL عند تجاوز ~5–10 آلاف طالب أو عند تعدد المدارس.
7. **تقسيم الواجهة**: `App.jsx` صار كبيراً (~1100 سطر) — يُقسّم إلى مكوّنات وصفحات.

---

## أفكار UX سريعة الأثر

- زر «إضافة طالب» عائم في كل شاشة.
- ملخص أعلى نموذج التسجيل (اكتمال الحقول %) قبل الإرسال.
- حفظ مسودة التسجيل في المتصفح حتى لا تُفقد البيانات.
- شارة حالة واضحة (قيد المراجعة / مقبول / مرفوض) بألوان.
- اختصارات لوحة مفاتيح للتنقل بين الصفحات.

## مؤشرات نجاح مقترحة

| المؤشر | الهدف |
|---|---|
| وقت إكمال طلب التسجيل | أقل من 3 دقائق |
| نسبة الطلبات المكتملة | > 90% |
| زمن استجابة لوحة القيادة | < 500ms |
| نسبة الأخطاء في الـ API | < 1% |
| نسخ احتياطي ناجح | 100% يومياً |
